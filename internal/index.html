🏗 How We Build Client Sites
1

Get the lead

Jarvis scrapes businesses without websites via Google Maps. We target restaurants, barbershops, nail salons, landscapers, plumbers, HVAC, electricians, auto shops, cleaning companies.

2

Build the demo first

Build a demo site before reaching out. Use one of our 10 industry templates. Each site is a single HTML file. Keep it clean, mobile-first, fast.

3

Create a dedicated repo

Every client gets their own GitHub repo — NEVER add client work to the jfwebstudios.com repo. Name it: clientname.com or client-project.

4

Host the demo

Push to GitHub Pages. Demo lives at jfwebstudios.com/demos/clientname/ for preview only.

5

Send cold outreach

Jarvis sends a personalized cold email + SMS. No pricing in messages — always push to a free quote call.

6

Close the deal

Jhonnatan calls the lead. After payment, connect their domain, go live within 48 hours.

📋 Hard Rules

One site = one repo Critical

Never mix client work into jfwebstudios.com. If a client needs their own domain, create a brand new repo. No exceptions.

Never mention price in outreach Critical

No $400, no "48 hours", no pricing in any cold email or SMS. Always redirect to a free quote consultation.

Email sending limits Important

Max 50 emails per batch. Wait 30 minutes between batches. Never more than 200/day. Violating this can get Gmail suspended.

Never touch the CNAME file Critical

The CNAME in jfwebstudios.com repo must always point to jfwebstudios.com. Changing it takes the main site down.

Plain text cold emails only Important

No HTML, no images, no emoji in subject lines, no ALL CAPS. Plain text lands in inbox, HTML goes to spam.

✅ Do's & Don'ts

Do

  • Build demo first, pitch second
  • Personalize every email
  • Keep sites mobile-first
  • Create a new repo per client
  • Always sign as Jhonnatan
  • Push free quote, not price

Don't

  • Quote price in cold outreach
  • Touch the main site repo
  • Send HTML cold emails
  • Send more than 50/batch
  • Mix clients in one repo
  • Promise specific timelines
